Edora AI Tutor

Plugin Moodle de tutorat intelligent basé sur une architecture RAG — le chatbot répond aux questions des étudiants à partir du contenu indexé du cours, enrichi d'un système de détection de niveau, de gamification XP et de génération d'images pédagogiques.

Moodle 4.4 (Bitnami)
FastAPI + ChromaDB
Gemini 2.5 Flash
Stage Edora LMS — été 2026

Installation

Mise en place complète de l'environnement depuis zéro.

1 — Prérequis

  • ✓ Docker Desktop installé et démarré
  • ✓ Python 3.10+ pour le microservice
  • ✓ Clé API Google Gemini valide
  • ✓ Git pour cloner le repo

2 — Cloner le dépôt

git clone https://github.com/islemTroudi/edora-ai-tutor
cd edora-ai-tutor

3 — Configurer les variables d'environnement

Créer un fichier .env à la racine du projet :

# Moodle
MOODLE_WS_TOKEN=votre_token_webservice
MOODLE_BASE_URL=http://localhost:8082

# Google Gemini
GEMINI_API_KEY=votre_cle_api_gemini

# Timeout LLM (optionnel, défaut 30s)
GEMINI_TIMEOUT=30
⚠️

Ne jamais commiter le fichier .env dans Git. Il est listé dans .gitignore — vérifier avant chaque push.

4 — Démarrer Moodle via Docker

# Démarrer les conteneurs (première fois)
docker compose up -d

# Vérifier que les conteneurs tournent
docker ps
# → edora-moodle et edora-mariadb doivent apparaître

5 — Installer le plugin Moodle

Copier le plugin dans Moodle
Copier le dossier moodle-plugin/blocks/tutor_ai/ dans le conteneur Docker sous /bitnami/moodle/blocks/tutor_ai/.
Déclencher l'installation
Se connecter en admin sur http://localhost:8082. Moodle détecte automatiquement le nouveau plugin et affiche la page d'installation. Cliquer sur "Upgrade database".
Générer un token WebService
Administration → Plugins → Web services → Gérer les tokens → créer un token pour l'utilisateur admin avec le service edora_ai_service. Mettre à jour le .env.
Ajouter le bloc à un cours
Dans un cours → Activer le mode édition → Ajouter un bloc → sélectionner "AI Tutor". Le chat apparaît dans la colonne latérale.

6 — Démarrer le microservice FastAPI

cd ai-service
pip install -r requirements.txt
uvicorn main:app --reload --port 8000

Vérifier que tout fonctionne :

curl http://localhost:8000/health
# → {"status": "ok", "version": "1.0.0"}

Pipeline RAG

Le flux complet d'indexation et de réponse — de l'upload du prof à la réponse de l'étudiant.

Indexation (upload prof → ChromaDB)

👨‍🏫
Prof uploade un fichier dans Moodle
Formats supportés : PDF, DOCX, PPTX, TXT, pages Moodle
↓
🔔
Observer PHP détecte l'événement
events.php + observer.php → appel HTTP vers /upload-resource
↓
📥
FastAPI télécharge le fichier via l'API Moodle
Utilise MOODLE_WS_TOKEN pour authentification
↓
📄
document_extractor.py — extraction texte
Selon le type : pdfplumber / python-docx / python-pptx / texte brut
↓
✂️
chunker.py — découpage LangChain
RecursiveCharacterTextSplitter — chunks sémantiquement cohérents
↓
🔢
embeddings.py — vecteurs Gemini
gemini-embedding-2 → vecteurs 3072 dimensions par chunk
↓
🗃️
chroma_service.py — stockage ChromaDB
Collection nommée course_{course_id} — persistant dans chroma_db/

Interrogation (question étudiant → réponse)

💬
Étudiant pose une question dans le chat
Paramètres envoyés : question + course_id + student_id + conversation_id
↓
🔍
Recherche vectorielle dans ChromaDB
Filtré par course_id → top-k chunks les plus pertinents
↓
🧠
Construction du prompt RAG
gemini.py : build_context() + build_history() + build_prompt()
↓
✨
Appel API Gemini 2.5 Flash
temperature=0.3 · max_output_tokens=1024 · timeout=30s · HISTORY_WINDOW=6
↓
🤖
Réponse du tuteur Edo
Adaptée au niveau de l'étudiant (Débutant / Intermédiaire / Avancé)

Endpoints API

Contrat REST du microservice FastAPI — port 8000.

GET
/health
Vérification de santé du service. Retourne {"status": "ok", "version": "1.0.0"}.
POST
/ask
Pipeline RAG complet. Reçoit question, course_id, student_id, conversation_id, conversation_history. Retourne la réponse d'Edo + chunks_used + found_in_course.
POST
/upload-resource
Déclenché par l'observer PHP. Reçoit course_id, resource_id, resource_type, file_url. Lance le pipeline d'indexation complet.
POST
/quiz
Génère minimum 3 QCM avec 4 propositions chacun. Retourne JSON structuré : {"questions": [{"question", "options", "answer", "explanation"}]}.
POST
/summary
Génère un résumé structuré avec titres, points clés, et reformulation pédagogique claire basé sur les chunks du cours.
POST
/examples
Génère 2-3 exemples concrets avec contexte réel à partir du contenu du cours. Prompt dédié, optimisé pour la pédagogie.
POST
/generate-image
Génère un diagramme éducatif via gemini-2.5-flash-image. Si concept est vide → mode galerie (top 3 concepts extraits de ChromaDB, 3 images max). Si concept précis → image ciblée.
POST
/reformulate
Reformule une explication selon un niveau de langage (slider "Explain Like I'm"). Niveaux : 5 ans, collégien, lycéen, étudiant, expert.
GET
/xp
Récupère les points XP et le rang de l'étudiant.
POST
/xp/add
Ajoute des points XP à l'étudiant suite à une interaction pédagogique.
GET
/unanswered
Retourne les questions auxquelles Edo n'a pas pu répondre (non trouvées dans le cours) — utilisé dans le dashboard prof.
POST
/export
Génère un PDF exportable de la session de chat via reportlab + Gemini. Téléchargeable depuis le chat.

Base de données

Tables MariaDB créées par le plugin (préfixe mdl_edora_).

🗂️ mdl_edora_conversations
PK id INT
FK course_id INT
FK student_id INT
conversation_id VARCHAR
student_level VARCHAR
created_at TIMESTAMP
💬 mdl_edora_messages
PK id INT
FK conversation_id VARCHAR
role ENUM(user,assistant)
content TEXT
created_at TIMESTAMP
🏆 mdl_edora_xp
PK id INT
FK student_id INT
FK course_id INT
points INT
rank VARCHAR
updated_at TIMESTAMP
❓ mdl_edora_unanswered
PK id INT
FK course_id INT
FK student_id INT
question TEXT
created_at TIMESTAMP
💡

Le préfixe mdl_ est obligatoire pour toutes les tables créées par un plugin Moodle. Dans les requêtes SQL, toujours utiliser {table_name} (la notation Moodle avec accolades) pour que le préfixe soit injecté automatiquement — ne jamais hardcoder mdl_ directement dans le code PHP.

Chat & Tuteur Edo

Le chatbot IA personnalisé au cœur du plugin.

🤖 Persona Edo — 7 règles
  • ① Répond uniquement dans la langue de l'étudiant (FR/AR/EN auto-détecté)
  • ② Se base exclusivement sur le contenu du cours indexé
  • ③ Adapte son niveau d'explication au niveau détecté de l'étudiant
  • ④ Ton chaleureux, encourageant, pédagogique — jamais condescendant
  • ⑤ Répond "je ne sais pas" (proprement) si l'info n'est pas dans le cours
  • ⑥ Historique des 6 derniers messages conservé (HISTORY_WINDOW = 6)
  • ⑦ Réponses concises et directes — max 1024 tokens

Détection de niveau étudiant

À la première vraie question pédagogique (pas un simple "bonjour"), Edo déclenche un mini-quiz de 10 questions. Le score détermine le niveau :

🌱
Débutant
0–4 / 10
📘
Intermédiaire
5–7 / 10
🚀
Avancé
8–10 / 10

Le niveau est stocké dans mdl_edora_conversations.student_level et utilisé dans chaque appel Gemini pour adapter le prompt.

Icônes d'action

4 boutons fonctionnels dans l'interface chat — chacun a un prompt dédié côté FastAPI.

📝 Quiz

Génère minimum 3 QCM avec 4 propositions chacun via /quiz. Format JSON structuré avec question, options A/B/C/D, bonne réponse et explication. L'étudiant voit un interface interactif dans le chat.

📋 Résumé

Prompt dédié sur /summary → résumé structuré avec titres, points clés, et reformulation pédagogique claire du cours ou du sujet posé.

💡 Exemples

Prompt dédié sur /examples → 2-3 exemples concrets avec contexte réel. Ancre les concepts abstraits du cours dans des situations concrètes.

🔍 Expliquer

Déclenche la détection de niveau avant d'expliquer. Reformule ensuite l'explication selon le niveau détecté. Inclut le slider "Explain Like I'm" (5 niveaux via /reformulate).

Gamification XP

Système de points d'expérience pour motiver l'engagement des étudiants.

Widget XP

Le widget s'affiche dans le chat (avant le div edo-messages). Il comprend :

  • ✓ Affichage du total XP et du rang de l'étudiant
  • ✓ Badge rouge sur la cloche 🔔 avec compteur de badges
  • ✓ Panneau notifications ouvert/fermé au clic
  • ✓ Fermeture au clic extérieur
  • ✓ "Tout voir" / "Réduire" pour les badges supplémentaires

Attribution XP

Les points sont attribués automatiquement via POST /xp/add à chaque interaction pédagogique dans le chat. Les données sont stockées dans mdl_edora_xp.

Dashboards

Tableaux de bord analytiques pour enseignants et administrateurs.

Dashboard enseignant

  • ✓ Questions non répondues par Edo (lacunes de contenu)
  • ✓ Engagement des étudiants par cours
  • ✓ Filtres période (semaine / mois / tout)
  • ✓ Détection rôle enseignant corrigée

Dashboard admin

  • ✓ Vue globale multi-cours
  • ✓ Top cours par activité IA
  • ✓ Distribution des tâches (quiz / résumé / exemples / chat)
  • ✓ Progression des niveaux étudiants
  • ✓ Filtres période avec alias SQL corrects ($period_filter / $period_filter_no_alias)
  • ✓ Mode sombre (bouton soleil/lune SVG)
⚠️

Attention aux alias SQL dans les requêtes du dashboard. Les requêtes avec alias ec utilisent $period_filter (filtre avec alias), les requêtes sans alias utilisent $period_filter_no_alias. Mélanger les deux cause une erreur Unknown column ec.created_at.

Génération d'images

Diagrammes éducatifs générés par gemini-2.5-flash-image.

Deux modes de génération

🎯 Concept précis

L'étudiant précise un concept (ex. "génère une image sur les pointeurs en C"). Edo demande confirmation du concept, puis génère une image ciblée et claire. Résultat optimal.

🗺️ Aperçu du cours complet

Si aucun concept n'est précisé, le flow multi-images se déclenche :

Requête ChromaDB générique
Top 3 chunks les plus représentatifs du cours récupérés via une requête "concepts principaux du cours".
Extraction des concepts clés
Gemini extrait 3 concepts clés depuis ces chunks.
Génération galerie (3 images max)
Une image par concept. Limité à 3 pour contrôler les coûts API. Un loader est affiché pendant la génération (~3× plus long).
⚠️

Pour un cours dense avec beaucoup de concepts, l'image "aperçu complet" peut être illisible. Recommander aux étudiants de préciser un concept pour des résultats optimaux. Le prompt est limité aux top 3 chunks pour éviter la surcharge contextuelle.

Prompt technique

specific_concept = (
    f"\n=== SPECIFIC CONCEPT REQUESTED ===\n{request.concept}\n"
    "Focus the image EXCLUSIVELY on this concept.\n"
    if request.concept else
    "\n=== COURSE OVERVIEW REQUESTED ===\n"
    "Generate a SINGLE comprehensive diagram that visually\n"
    "represents ALL the main concepts of this course and\n"
    "their relationships. The diagram must be a global overview\n"
    "— like a visual syllabus — showing how key topics connect.\n"
)

Troubleshooting

Problèmes connus et leurs solutions.

Erreur Unknown column ec.created_at

Cause : Requête SQL avec alias ec utilisant $period_filter_no_alias (ou vice-versa).
Fix : Utiliser $period_filter (avec alias ec.) pour les requêtes avec alias, $period_filter_no_alias pour les requêtes sans alias.

Bug Boucle de redirection admin dashboard

Cause : $PAGE->set_url() pointait vers dashboard.php au lieu de admin_dashboard.php.
Fix : Corriger l'URL dans set_url() pour pointer vers le bon fichier.

Attention Confusion entre cours dans les réponses RAG

Cause : Recherche ChromaDB sans filtre course_id.
Fix : Toujours passer where={"course_id": course_id} dans la requête ChromaDB.

Attention Timeout Gemini sur les requêtes longues

Cause : Génération lente sur de grands contextes ou pics de charge.
Fix : Augmenter GEMINI_TIMEOUT dans .env (ex: 60s pour la génération d'images).

Attention Plugin non détecté par Moodle après copie

Cause : Cache Moodle non vidé.
Fix : Administration → Développement → Vider tous les caches, puis recharger la page admin.
